# NE301 Device Configuration File Reference (v4.3.1 / Config Schema v2)

> Applies to the device configuration JSON downloaded from the web page "Firmware Upgrade → Export" (endpoints: `GET /api/v1/device/config/export` and `POST /api/v1/device/config/import`).
> Field meanings, defaults, and ranges follow the firmware code (structs in `Custom/Core/System/json_config_mgr.h`, defaults and normalization in `json_config_mgr.c`, enums in the service layers); web page entries follow the actual frontend.

## Import semantics (read this first)

- **Merge, not rebuild**: import overlays only the keys actually present in the file; keys missing (or deliberately deleted) keep the **device's current values** — they do not revert to factory defaults.
- **Version gate**: files whose `config_version` is newer than the firmware's current version (2) are rejected wholesale; v1 files still import, and the persisted version marker is pinned back to 2 after import.
- **Network params always persist**: importing network fields writes RAM+NVS immediately, whether or not the device is connected — no field is skipped or rejected because a link is up. Each field then takes effect when its consumer next reads it (mostly at next restart / next connect — see the note under `network_service`).
- Import column markers used in the tables:
  - ✅ imported and applied
  - 📄 export-only documentation, **ignored on import** (device-bound info or source-device runtime snapshot)
  - 🔧 imported, but normalized/clamped first (see each table)
- Sensitive data: the file carries the WiFi password, MQTT password, RTSP password, RTMP stream key, webhook secret, and admin password **in plaintext** — handle with care.

## ⚠️ Fields not actually used by the current firmware

The following fields are **stored, exported, and round-tripped on import**, but **nothing in the firmware reads them** — setting them changes no behavior (importing them is harmless too). Most are legacy or reserved; verified by grepping the v4.3.1 code:

| Field | Notes |
|---|---|
| `device_service.image_config.brightness` / `contrast` | No consumer (the web UI does not expose them in this release either) |
| `device_service.image_config.aec` | Auto-exposure switch: no consumer |
| `device_service.image_config.capture_disable_comm` | Copied/logged inside the device service only; the capture-upload path never reads it — no effect observed |
| `work_mode_config.work_mode` / `image_mode.enable` | The firmware has a single work mode (image/capture); neither field is consumed |
| `work_mode_config.video_stream_mode.enable` | Legacy work-mode parent switch: streaming is gated by rtmp_enable / rtsp_enable independently — this switch has no consumer |
| `work_mode_config.io_trigger[]` entire group (`pin_number`/`enable`/`input_enable`/`output_enable`/`input_trigger_type`/`output_trigger_type`) | The registration API exists but has no callers; the web serialization code is commented out — not wired up |
| `capture_upload_config.max_pending_records` | Stored and shown on the web only; the upload pipeline never reads this cap |
| `network_service.poe.dhcp_retry_interval_ms` | Not read by the PoE driver |
| `network_service.cellular.authentication` / `operator` | Not used by the cellular modem configuration |
| `auth_mgr.session_timeout_ms` / `enable_session_timeout` | No session-timeout logic on login — not consumed |

For contrast, fields that look unused but **are** used: the whole `ai_debug` group (`ai_enabled`/`ai_1_active`/`confidence_threshold`/`nms_threshold`/`overlay_results`/`inference_interval_ms` are pushed through the AI service into the video nodes and model post-processing; `ai_1_active` also selects the model slot for wake captures), `light_config.light_threshold` (light-control check on the wake path), and the MQTT buffer/timeout parameters (`tx_buf_size`/`rx_buf_size`/`outbox_expired_timeout_ms` etc. are consumed by the MQTT client library).

| Field group | Takes effect at |
|---|---|
| `poe.*` | Next restart (boot applies the config while bringing the interface up), the next connect attempt, or a web re-save; a link already up at import time is not reconfigured live |

## Appendix: import behavior quick reference

| Category | Fields |
|---|---|
| Never imported (export-only) | The whole `device_info`; `light_config.connected`; `power_mode_config.last_activity_time / mode_switch_count`; the known-networks `rssi / channel / connected / is_known / last_connected_time`; `checksum / timestamp` (recomputed by the device) |
| Imported with special handling | `current_mode / default_mode` (out-of-domain ignored); `last_activity_time` (re-stamped locally); MQTT `*_cert_data` (Flash rewritten only when carried); the count fields (clamped); `capture_upload_config` normalized as a whole; `ap_sleep_time / wifi_country_code` out-of-set → treated as absent, device value kept; `sys_clk_profile` (validated, reboot-applied); `config_version` (gated + pinned) |
| Hand-edited file protection | Counts shrink when arrays shrink (time nodes / known networks / upload schedule); `time_node_count` capped at 10; `interval_mode / start_time / end_time / anchor_time` out-of-domain ignored; files with a version newer than the firmware rejected wholesale |
