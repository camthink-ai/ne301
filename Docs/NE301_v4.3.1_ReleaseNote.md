## Overview

v4.3.1 is the largest release since v2.1.0: the Flash partition and memory layouts were restructured, the WiFi host stack was fully migrated to the WiseConnect 4.1.1 SDK, a new capture-upload pipeline and one-click bundle upgrade were introduced, along with extensive field-stability fixes.

## Highlights — New Features

- **One-click bundle upgrade (OTA Bundle)**: `make pkg-bundle` packs all firmware into a single file that upgrades the whole device in one web upload — layout migration for partition-table changes, optional skip of same-version entries, cross-model packages hard-rejected, FSBL payload verified before writing.
- **WiFi subsystem overhaul**: host driver migrated to the WiseConnect 4.1.1 SDK; new WiFi firmware OTA upgrade (automatic mismatch guidance); WiFi region code (us / eu / jp / kr / cn); host-side AP DHCP server with sticky leases; a series of SPI-bus and host-stack hardening fixes.
- **Capture-upload pipeline**: four upload modes (instant / batch / scheduled / local-only), MQTT batch publishing and webhook delivery, power-aware wake scheduling, SD hot-plug auto-switching, a web management UI and REST API.
- **Full HaLow (802.11ah) support**: mm6108 / mm8108 build-time chip switch, web configuration for radio parameters and extended country codes, a web power-save switch (default off), and software-enforced mutual exclusion with PoE / 4G.
- **Web management UI overhaul**: dedicated Web partition with automatic fallback into the built-in Web Recovery; file management (Flash / SD); a firmware-upgrade center covering APP / Web / Model / FSBL / WiFi / bundle with expected-version checks; a major connection & stream-stability rework.
- **AI & models**: unified build-time selection of the STEdgeAI 2.2 / 3.0 / 4.0 runtimes (this release line is 4.x); AI partitions enlarged to 8MB A/B slots; new pose estimation, pointer-meter reading, instance segmentation, and BlazeFace face detection.

## Highlights — Fixes

- Black screen for late-joining live-preview clients: clients are now keyframe-synced individually; join latency at most one GOP.
- Web connection & stream-stability overhaul: one-request connections, static-asset etag/304 caching, FIFO-copied video frames, per-client WS send-buffer cap — eliminating `err_network` popups and smearing on the phone link.
- Video-pipeline stop deadlock: `video_pipeline_stop()` is now bounded by 3 s with force-termination, no longer wedging the HTTP task.
- Startup-decision timer-thread stack overflow HardFault: the decision now runs on a dedicated large-stack thread.
- JPEG tail truncation: fixes bottom-mosaic and incomplete rendering in browser previews.
- XSPI erase busy-poll watchdog starvation: eliminates silent resets with no log in the field.
- RTMP push: fixed last-NAL truncation (bottom-row macroblock errors); the push now auto-starts at boot instead of sitting idle (~6 minutes of lost footage per reboot previously).
- Camera & encoder: fixed torn frames from buffer races and the encoder's cold-start all-INTRA latch (now escapes automatically via a QP-floor step-up).
- Config import no longer resets omitted settings: importing a configuration file merges onto the device's current configuration — keys missing from the file (including ones deliberately deleted from an export) keep the device's own values instead of reverting to factory defaults, and device-bound identity (MAC / serial number / hardware version) is no longer overwritten by the source device. Recently added settings (timer-capture daily lattice, RTMP/RTSP stream, webhook, capture-upload policy, work frequency) now also round-trip through export/import.

## ⚠️ Upgrade Notes

1. **Upgrade in sequence**: the Flash partition table was redesigned — upgrading from v2.1.0 must follow
   **SensorExt APP → Web Recovery → Web → FSBL → WiFi → Model → optional HaLow APP**.
   **Do not use the HaLow APP for the first step**; skipping or reordering steps leaves the Web interface inaccessible. See the [OTA Update Guide](./NE301_v4.3.1_OTA_Update_Guide.md).
2. **Internal Flash is reformatted on the first boot** (the LittleFS partition moved): **MQTT TLS CA / client-certificate / private-key files are lost** — if MQTTS is enabled, back them up before upgrading and upload them again afterwards. Configuration, WiFi credentials and other NVS data, and all SD-card data, are preserved.
3. **Companion version requirements**: WiFi firmware `2.16.5.108`, FSBL `1.0.3.1`, and 4.x-prefixed model packages (aligned with the APP major version, otherwise a version-check warning triggers).
4. **Firmware package model gate**: OTA headers carry the device model; cross-model packages (e.g., an NE302 package on an NE301) are rejected. Unstamped legacy packages are allowed through.
5. Once on this release, future full-device upgrades (including partition-table changes) can use the **one-click bundle upgrade** — no more per-firmware manual handling.

## Known Issues

- The WiFi firmware OTA push stage takes ~1–3 minutes. Do not power off during this process.
- Bundle burns do not use AB slots (forced direct burn). Do not close the browser page or power off during a bundle burn.
