# NE301 v4.3.1 OTA Update Guide

> **English** | [中文](./NE301_v4.3.1_OTA_Update_Guide_cn.md)

> **Applicable Scenario**: Upgrading from NE301 **v2.1.0** (commit `0198d97`) to **v4.3.1**
>
> **Prerequisites**: The device is running the old firmware normally. All OTA firmware files are ready on your PC.
>
> ⚠️ **IMPORTANT**: v4.3.1 redesigns the Flash partition table with a **brand-new independent Web partition** (which did not exist in v2.1.0). The upgrade **must follow the exact steps and sequence** in this guide. Skipping steps or reordering them will result in the Web interface becoming inaccessible. Additionally, v4.3.1 moves to the STEdgeAI 4.x line — the **WiFi firmware must be upgraded to `2.16.5.108`** and the **AI model package must be 4.x**.
>
> ⚠️ **INTERNAL STORAGE IS REFORMATTED**: v4.3.1 relocated the internal Flash LittleFS partition. On the first boot after the APP upgrade the device reformats it automatically. Ordinary v2.1.0 snapshots were not stored on internal Flash; however, **MQTT TLS CA, client-certificate, and private-key files are stored in LittleFS and will be lost**. If MQTTS is enabled, preserve the original certificate/key files **before Step 1** and upload them again after the upgrade. Configuration, WiFi credentials and other NVS data are preserved, and SD-card data is unaffected.
>
> ⚠️ **Use the SensorExt (sensor-extension) APP firmware during this upgrade**: the HaLow APP firmware exceeds 3.5MB and, when written to slot A, overwrites the old version's WEB partition — a rollback would then leave the Web server unable to start (see Step 1). Users needing HaLow should complete all steps first, then upgrade to the HaLow APP separately (Step 8).

## Upgrade Overview

The partition redesign moved the Web assets into a dedicated Flash partition. After the APP is upgraded, the old Web assets are no longer accessible — the device will automatically enter the built-in Web Recovery mode. The upgrade must be performed in the following sequence:

```
Old Version (v2.1.0)
    │
    ├── 1. Upload new APP firmware (v4.3.1, **SensorExt build** — see Step 1) → Device reboots → APP upgrade complete
    │
    ├── 2. Connect to device WiFi → Open browser → Enter Web Recovery mode
    │     (Reason: Web partition address changed; old Web assets are no longer accessible)
    │
    ├── 3. On Recovery page → Upload new Web OTA firmware (1.5.0.7) → Page auto-recovers
    │     (Web assets reload automatically after upload — no reboot needed)
    │
    ├── 4. Enter normal UI → System prompts FSBL version mismatch → Follow guided upgrade (1.0.3.1)
    │     (If no prompt: System Settings → Firmware Upgrade → Import → Advanced → FSBL Upgrade)
    │
    ├── 5. Reconnect WiFi → System prompts WiFi version mismatch → Follow guided upgrade (2.16.5.108)
    │     (If no prompt: System Settings → Firmware Upgrade → Import → Advanced → WiFi Upgrade)
    │     ⏳ WiFi firmware push to chip takes ~1–3 minutes — please be patient
    │
    ├── 6. Upload a 4.x model package (required — AI partitions also moved)
    │     (Old model — factory default or previously OTA'd — is no longer
    │      visible to the new APP; AI detection is unavailable until done)
    │
    ├── 7. Upgrade complete → Verify version information
    │
    └── 8. (Optional, for HaLow users) Upgrade the APP to the HaLow build
          separately (safe now: the WEB partition no longer sits next to
          the APP partitions in the new layout)
```

### Why Is This Process Necessary?

| Change                              | Impact                                                            |
|-------------------------------------|-------------------------------------------------------------------|
| Web partition now independent | Old APP has no concept of this partition; Web assets are lost → triggers Recovery |
| FSBL expected version check (1.0.3.1)      | APP is built with `EXPECTED_FSBL_VERSION=1.0.3.1`; prompts on mismatch |
| WiFi firmware 2.16.5.108 + SDK upgrade | APP is built with `EXPECTED_WIFI_VERSION=2.16.5.108`; prompts on mismatch |
| APP major 2 → 4 (STEdgeAI 4.x line)        | Model package prefix must be 4.x, otherwise a version-check warning is shown |
| AI partition addresses moved                | Old model packages (including previously OTA'd ones) sit at addresses the new APP no longer reads → Step 6 is mandatory |
| Internal file system (LittleFS) partition moved | First boot reformats it automatically. Ordinary snapshots were not stored there, but MQTT TLS CA/client certificate/private key files are erased → MQTTS users must preserve originals before Step 1 and upload them again afterwards; NVS and SD data are preserved |
| HaLow APP firmware exceeds 3.5MB        | Writing it to slot A overwrites the old WEB partition → use the SensorExt APP throughout the upgrade (Step 1); flash the HaLow build separately afterwards (Step 8) |

## Preparation

### Required OTA Firmware Files

> **MQTTS users — do this before Step 1**: preserve the original MQTT TLS CA certificate, client certificate, and private-key files from your provisioning source. The files stored in internal LittleFS will be erased by the partition migration. After the firmware sequence is complete, upload these originals again and verify the MQTTS connection. NVS settings and SD-card files do not need migration.

| Filename                                    | Type   | Notes                            |
|--------------------------------------------|-------|----------------------------------|
| `ne301_App_signed_v4.3.1.x_SensorExt_pkg.bin` | APP | Main application OTA package (**use this build during the upgrade**, see note below) |
| `ne301_App_signed_v4.3.1.x_pkg.bin`        | APP (HaLow) | HaLow build — **only upgrade to it separately after all steps are complete** (see Step 8) |
| `ne301_Web_v1.5.0.7_pkg.bin`               | Web    | Web frontend assets OTA package  |
| `ne301_FSBL_signed_v1.0.3.1_pkg.bin`       | FSBL   | First Stage Boot Loader OTA pkg  |
| `ne301_Wifi_flash_v2.16.5.108_pkg.bin`     | WiFi   | SiWG917 wireless firmware OTA pkg (required) |
| `ne301_Model_v4.0.0.0_pkg.bin`             | Model  | AI model package for STEdgeAI 4.x (**required**, see Step 6) |

> ⚠️ **Why the SensorExt APP during the upgrade**: the HaLow APP firmware (which bundles the HaLow wireless firmware) exceeds 3.5MB. In the old version (v2.1.0) the WEB partition sits at the tail of APP slot A — if the OTA happens to write to slot A, the HaLow build overwrites and destroys the old WEB partition. If the new APP then fails to boot and the system rolls back, the old firmware's Web server cannot start either, leaving the device without a web upgrade path. The SensorExt build is much smaller and safe to write to either slot.

### Operating Environment

- A PC or phone that can connect to the device's WiFi hotspot
- Chrome / Edge browser recommended (use incognito mode if you encounter caching issues)

## Step 1: Upload the New APP Firmware

> **Goal**: Write the v4.3.1 APP firmware to Flash. After reboot, the new partition table and features take effect.

> ⚠️ **Select the SensorExt build** (`ne301_App_signed_v4.3.1.x_SensorExt_pkg.bin`); do **not** upload the HaLow build in this step. The HaLow firmware exceeds 3.5MB, and in v2.1.0 the WEB partition sits at the tail of APP slot A — if the OTA write target happens to be slot A, the tail of the HaLow image overwrites the old WEB partition. Should the new APP then fail to boot and roll back, the old firmware's Web server cannot start either, and the device can no longer be upgraded over the web. The SensorExt build (no bundled HaLow firmware, much smaller) is safe to write to either slot. HaLow users upgrade separately in Step 8 after completing everything.

### Steps

1. Ensure the device is running the old firmware normally. Connect your PC to the device's WiFi hotspot.
2. Open a browser and navigate to the device's Web management interface.
3. Go to **System Settings** → **Firmware Upgrade** → Click **Import Firmware**

![Import firmware entry](images/step1_import_entry.png)

4. In the Import Firmware dialog, click the **APP File** area to select a file.

![Select APP firmware](images/step1_select_app.png)

5. Select `ne301_App_signed_v4.3.1.x_SensorExt_pkg.bin`.
6. Wait for the upload to complete (progress is shown during upload).
7. Click the **Confirm Burn** button.

![Confirm burn](images/step1_confirm_burn.png)

8. The device will reboot automatically. A waiting screen will be displayed.

### Expected Result

- The device reboots automatically.
- After about 5–15 seconds, search for the device's WiFi hotspot again.

## Step 2: Web Firmware Recovery

> **Goal**: Enter Web Recovery mode in preparation for uploading the new Web firmware.

### Steps

1. Reconnect your PC to the device's WiFi hotspot.
2. Open a browser and enter the device's management address (or refresh the previous page).

3. You should see the **Web Recovery Mode** recovery page:

![Web Recovery page](images/step2_recovery_page.png)

> The page displays: "The device could not load a valid web firmware (the partition address may have changed after an upgrade, or the firmware was not flashed)."

4. **If the recovery page does not appear**, try:
   - Opening a new browser tab (incognito/private mode recommended).
   - Clearing the browser cache and refreshing (Ctrl+Shift+Del).
   - Switching to a different browser (Chrome → Edge → Firefox).

---

## Step 3: Upload the New Web OTA Firmware

> **Goal**: Upload the new Web firmware through the Recovery page to restore the normal Web UI.

### Steps

1. On the Web Recovery page, click the file selection area.
2. Select `ne301_Web_v1.5.0.7_pkg.bin`.

![Select Web firmware](images/step3_select_web.png)

3. Click the **Upload & Recover** button.
4. The progress bar will show real-time upload progress.

![Web upload progress](images/step3_upload_progress.png)

5. After a successful upload, the page displays "Recovery successful, reloading interface..." and **automatically refreshes** to the normal Web management interface after ~1.5 seconds.

![Recovery success](images/step3_recovery_success.png)

6. **If the page does not auto-refresh**: manually refresh the browser page (F5).

### Expected Result

- The normal Web management interface loads successfully.
- All function menus are visible.

## Step 4: FSBL Firmware Upgrade

> **Goal**: Update the FSBL to `1.0.3.1` and clear the version mismatch warning.

### Automatic Prompt

1. In the Web management interface, go to **System Settings** → **Firmware Upgrade**.

2. Check the **FSBL Version** row — if the current version does not match the expected version (`1.0.3.1`), a **prompt icon** appears on the right:

![FSBL version mismatch prompt](images/step4_fsbl_mismatch.png)

3. Click the icon to open a dialog showing the current version vs. the expected version:

![FSBL mismatch dialog](images/step4_fsbl_dialog.png)

4. Click **Upgrade Now** to jump to the FSBL upgrade page.

### Manual Entry

If no automatic prompt appears: **System Settings** → **Firmware Upgrade** → **Import Firmware** → **Advanced Options** (bottom-left) → **FSBL Firmware Upgrade**

![Advanced options menu](images/step4_advanced_menu.png)

### Upload and Complete

1. On the FSBL upgrade page, click the file selection area.
2. Select `ne301_FSBL_signed_v1.0.3.1_pkg.bin`.

![Select FSBL firmware](images/step4_select_fsbl_file.png)

3. Click **Confirm Burn**. The device will reboot to complete the FSBL upgrade.

> ⚠️ **Note**: After clicking **Confirm Burn**, the page may appear unresponsive. However, the device has actually completed the FSBL upgrade in the background and is rebooting. Wait about 5–10 seconds, reconnect to the device's WiFi, and go to **System Settings → Firmware Upgrade** to verify the FSBL version has been updated.

### Expected Result

- After the device reboots, reconnect WiFi and go to Web → System Settings → Firmware Upgrade → FSBL version displays `1.0.3.1` (prompt icon disappears).

## Step 5: WiFi Firmware Upgrade

> **Goal**: Update the SiWG917 wireless chip firmware to `2.16.5.108`. This is **required** for v4.3.1.

⚠️ **Note**: Pushing the WiFi firmware to the SiWG917 chip's internal storage takes approximately **1–3 minutes** — the longest step in the entire process. Please be patient and **do not power off the device** during this step.

### Automatic Prompt

1. Reconnect your PC to the device's WiFi, enter the Web management interface → **System Settings** → **Firmware Upgrade**.

2. Check the **WiFi Version** row:
   - **Flash version** ≠ **Running version**: a prompt icon appears.
   - Both match but ≠ **Expected version** (`2.16.5.108`): a prompt icon appears.

![WiFi version prompt](images/step5_wifi_mismatch.png)

3. Click the prompt icon → **Upgrade Now**.

### Manual Entry

**System Settings** → **Firmware Upgrade** → **Import Firmware** → **Advanced Options** → **WiFi Firmware Upgrade**

### Steps

1. On the WiFi upgrade page, click the file selection area.
2. Select `ne301_Wifi_flash_v2.16.5.108_pkg.bin`.

![Select WiFi firmware](images/step5_select_wifi_file.png)

3. After the file upload completes, click **Confirm Upgrade**.
4. A confirmation dialog appears. Review and click **Confirm**.

![WiFi confirm upgrade](images/step5_confirm_wifi.png)

5. The device reboots and begins pushing the WiFi firmware.

### Wait for Completion

What happens after reboot:
- The LED **blinks rapidly** (WiFi firmware is being pushed to the SiWG917 chip).
- The WiFi hotspot will disconnect and needs to be manually reconnected after the update completes.
- The PC frontend polls the device (every 5 seconds, up to 60 seconds) to detect when it is back online.

If the frontend cannot detect the device, the page redirects to the **LED Guidance waiting page** (`/upgrade-waiting`):

![LED waiting page](images/step5_led_waiting.png)

Use the LED to determine status:
- **LED solid on** → Upgrade complete.
- **LED blinking** → Upgrade in progress.
- **LED off** → Abnormal or device entered sleep mode. Try pressing and holding the button for 2+ seconds to wake.

### Expected Result

- On the Firmware Upgrade page, WiFi version displays `2.16.5.108` (Flash and running versions match).

## Step 6: Update the AI Model Package

> **Goal**: Restore AI functionality with a 4.x model package. **This step is required for every device coming from v2.1.0 — it cannot be skipped.**

### Why this step cannot be skipped

v4.3.1 moved the AI partitions in Flash (old: AI_Default @ `0x70900000`, AI_1 @ `0x70E00000`, AI_2 @ `0x71300000` → new: AI_1 @ `0x70900000`, AI_2 @ `0x71100000`). The new APP only reads the new addresses, so the old model — factory default or one you OTA'd yourself — is no longer visible to it. Depending on the device's slot state, the Firmware Upgrade page will show one of:

- **Model version shows 2.x** — that is the old *factory default* model (its header happens to sit at the new AI_1 base address). A 2.x model cannot run on the STEdgeAI 4.x runtime, so AI detection stays unavailable.
- **Model version shows empty / `0.0.0.0`** — a model you OTA'd on the old firmware sits at an address the new firmware no longer reads. This is **expected behavior, not a failed upgrade**.

In both cases, upload a 4.x model package:

1. Go to **System Settings** → **Firmware Upgrade** → **Import Firmware**.
2. In the dialog, select the **AI Model** file area and choose `ne301_Model_v4.0.0.0_pkg.bin`.
3. Click **Confirm Burn** and wait for completion — the page restarts the device automatically as part of the burn.
4. After the reboot the new model is loaded and AI detection recovers. The model is only loaded at boot: if you closed the dialog without clicking **Confirm Burn**, restart manually (drawer menu → **Restart Device**).

> The old model data left behind in Flash is harmless — it is progressively overwritten by subsequent model upgrades (A/B slots). No cleanup is needed.

> ⚠️ **Custom model users**: a custom 2.x model package cannot be carried over. Re-package your model with the STEdgeAI 4.x toolchain before uploading; the stock `ne301_Model_v4.0.0.0_pkg.bin` package only restores the standard model.

## Step 7: Verify the Upgrade

1. Go to **System Settings** → **Firmware Upgrade**.
2. Verify the following version information:

| Component        | Expected Version | Status          |
|-----------------|-----------------|-----------------|
| APP Version      | 4.3.1.x         | ✓               |
| Web Version      | 1.5.0.7         | ✓               |
| FSBL Version     | 1.0.3.1         | ✓ No prompt icon |
| WiFi Version     | 2.16.5.108      | ✓ No prompt icon |
| AI Model Version | 4.0.0.0         | ✓ No prompt icon |
| WakeCore         | 0.2.7.5         | ✓               |

![Verify versions](images/step6_verify_versions.png)

3. If all versions are correct and there are no prompt icons, the mandatory firmware sequence is complete.
4. If MQTTS is enabled, upload the preserved original MQTT TLS CA/client-certificate/private-key files again and verify the secure connection. Then continue to the optional HaLow APP step if needed.

## Step 8: Upgrade to the HaLow APP Firmware (Optional)

> **Goal**: For users who need HaLow (802.11ah), switch the APP from the SensorExt build to the HaLow build after Steps 1–7 are fully complete. Devices without a HaLow requirement stay on the SensorExt build and skip this step.

### Why it is only safe now

After the upgrade to v4.3.1, the WEB partition lives at its own address (`0x71900000`) and no longer sits next to the APP partitions — the HaLow build (over 3.5MB, still within the 4MB APP slot) can be written to either slot without touching the WEB partition. In the old layout at Step 1 the WEB partition sat at the tail of slot A, which is why the SensorExt build is mandatory during the upgrade.

### Steps

1. Go to **System Settings** → **Firmware Upgrade** → **Import Firmware**.
2. In the dialog, select the **APP File** area and choose `ne301_App_signed_v4.3.1.x_pkg.bin`.
3. Click **Confirm Burn**; the device reboots and completes the switch.

### Notes

- HaLow shares the EXTI15 interrupt line with PoE (W5500) — the two are hardware-exclusive, and HaLow also conflicts with 4G: enabling the HaLow link automatically stops PoE and 4G.
- The APP version number stays 4.3.1.x after the switch; only the feature variant changes.

## FAQ

### Q: What if the device loses power during the upgrade?

- **Power loss during APP upgrade**: The A/B partition protection mechanism keeps the old slot firmware intact. The device will boot from the old slot on next power-up. The new slot is marked `UNBOOTABLE` and the system rolls back automatically.
- **Power loss during FSBL upgrade**: FSBL corruption will prevent the device from booting. Re-flash via JTAG/SWD.
- **Power loss during WiFi upgrade**: If power is lost while `.rps` is being pushed to the chip, WiFi may function abnormally after reboot. Re-enter the WiFi upgrade page and upload again.

### Q: The Web Recovery page does not appear?

- Open the browser in incognito/private mode and re-enter the device IP.
- Clear the browser cache.
- Try a different browser.
- Verify that your PC is connected to the device's WiFi hotspot.

### Q: The FSBL/WiFi upgrade prompt does not appear?

Manual paths:
- **FSBL**: System Settings → Firmware Upgrade → Import Firmware → Advanced Options → FSBL Firmware Upgrade
- **WiFi**: System Settings → Firmware Upgrade → Import Firmware → Advanced Options → WiFi Firmware Upgrade

### Q: Can I skip the WiFi upgrade?

**Not recommended.** v4.3.1 expects `2.16.5.108`; the firmware info page will keep showing a warning, and the SiWG917 will not expose this release's fixes. Upgrade it.

### Q: Can I skip the model package upgrade?

**No** (when coming from v2.1.0). The AI partitions moved in v4.3.1, so every model the old firmware could see — including one you OTA'd yourself — is at an address the new firmware no longer reads, and a 2.x model cannot run on the 4.x runtime anyway. Upload a 4.x model package as described in Step 6. Only devices already running a 4.x model package on the new partition layout (e.g. interim 4.x builds) may skip it.

### Q: Why can't I use the HaLow APP firmware in Step 1?

The HaLow build exceeds 3.5MB. In v2.1.0 the WEB partition sits at the tail of APP slot A — if the OTA write target is slot A, the tail of the image overwrites the WEB partition. Should the new APP fail to boot and roll back, the old firmware's Web server cannot start either, leaving the device without a web upgrade path. Flashing the HaLow build after the full upgrade (Step 8) carries no such risk — in the new partition layout the WEB partition is far away from the APP partitions.

### Q: AI detection still not working after uploading the model package?

The model is only loaded at boot. The **Confirm Burn** step restarts the device and completes the activation; if it was skipped, restart manually (drawer menu → **Restart Device**), then verify the AI Model version as described in Step 7.

### Q: What does the internal-storage reformat erase?

Ordinary v2.1.0 snapshots were not stored on internal Flash, but MQTT TLS CA, client-certificate, and private-key files were stored in LittleFS and are erased when that partition is reformatted. MQTTS users must preserve the original files before Step 1, upload them again after the upgrade, and verify the secure MQTT connection. Configuration, WiFi credentials and other NVS data, and all SD-card data, are preserved.

### Q: Cannot connect to the device after WiFi firmware upgrade?

1. Wait at least 3 minutes and observe the device LED.
2. LED is solid on but no WiFi hotspot → try rebooting the device.
3. Still not recovered → re-flash the full firmware package via JTAG/SWD.
