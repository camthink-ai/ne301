## 1. General Conventions

### 1.1 Service & Base URL

| Item | Value |
|---|---|
| HTTP service | Mongoose, listening on **TCP port 80** |
| HTTPS | Disabled (`IS_HTTPS=0`) |
| API base path | **`/api/v1`** |
| Max request body | 5 MB (normal requests through the router) |
| Connection | `Connection: close`, one request per connection |
| Static assets | Web UI served from `/` (ETag/304/gzip supported) |

Device address:
- STA / Ethernet mode: the IP obtained by the device (check the router/AP)
- AP mode: the device hotspot gateway address (default `10.10.10.1` subnet, subject to actual device configuration)

### 1.2 Authentication

- **HTTP Basic auth** per request; no sessions/cookies.
- Username is fixed to **`admin`** (`auth_mgr.h: AUTH_ADMIN_USERNAME`); the password is the device access password.
- The password can be verified via `POST /api/v1/login` and changed via `POST /api/v1/change-password`.

**Unauthenticated endpoints** (route table `require_auth=false`):

| Endpoint | Purpose |
|---|---|
| `POST /api/v1/login` | password verification |
| `GET /api/v1/preview/status` | preview status |
| `POST /api/v1/preview/start` | start preview |
| `POST /api/v1/preview/stop` | stop preview |

> Note: `POST /api/v1/system/ota/upload` is intercepted by the stream processor before route dispatch and handles auth itself — see §16.2.

**Auth failure response** (normal endpoints): HTTP status is still **200** with envelope `error_code: "UNAUTHORIZED"`. The stream upload endpoints (`files/upload`, `ota/upload`) are exceptions and return a real `401`.

### 1.3 Unified Response Envelope

All endpoints routed through the router return **HTTP 200 regardless of success or failure**, with a JSON envelope:

```jsonc
// success
{
  "success": true,
  "message": "Device information retrieved successfully",   // optional
  "data": { ... }                                            // optional
}

// failure
{
  "success": false,
  "error_code": "INVALID_PASSWORD",   // present only on failure
  "message": "Invalid password"
}
```

| Field | Type | Notes |
|---|---|---|
| success | bool | business outcome |
| error_code | string | present only on failure; upper-snake-case name (see 1.5) |
| message | string | human-readable description; may appear on success too |
| data | object/array/null | business payload; may be absent |

> **Clients must branch on the `success` field — never on the HTTP status code.**

### 1.4 Envelope Exceptions (real HTTP statuses / non-JSON)

| Endpoint | Response form |
|---|---|
| `GET /api/v1/files/download` | raw file bytes + `Content-Disposition` (404/400 still envelope JSON) |
| `GET /api/v1/files/preview` | raw bytes for images; JSON envelope for text files |
| `POST /api/v1/files/upload` | streamed; auth failure **401**, bad request 400, internal 500/503 (real statuses) |
| `POST /api/v1/system/ota/upload` | streamed; real statuses 400/401/500 |
| `POST /api/v1/system/ota/export` | raw firmware bytes + `Content-Disposition` |
| `/` static assets | 200/304/404 |
| `OPTIONS` preflight | 200 + CORS headers |

### 1.6 CORS & Preflight

All responses carry CORS headers (`Access-Control-Allow-Origin: *`, etc.); `OPTIONS` preflight is answered directly with 200 + CORS headers without entering business routing.

### 1.7 Live Preview Stream (WebSocket, not part of the HTTP API)

The preview stream runs on a separate WebSocket service: **`ws://<device-ip>:8081/stream`** (default port 8081, path `/stream`). See [Appendix B](#appendix-b-websocket-preview-stream).

## 3. Authentication Module (auth)

### 3.1 POST /api/v1/login — verify device password

**No auth.** Used by the login page to verify the password (username is fixed `admin` and not sent).

**Request body**

| Field | Type | Required | Description |
|---|---|---|---|
| password | string | yes | device access password |

**Response data**: `null` (success carries only `success:true` + message)

**Errors**: `INVALID_REQUEST` (missing param); `INVALID_PASSWORD` (1001, wrong password)

### 3.2 POST /api/v1/change-password — change device password

**Request body**

| Field | Type | Required | Description |
|---|---|---|---|
| password | string | yes | new password, **8–32 characters** |

**Response data**: `null`

**Notes**: takes effect immediately; subsequent requests must use the new password for Basic auth.

**Errors**: `INVALID_REQUEST` (missing/invalid length); `INVALID_PASSWORD` (change failed)

**Response data**

|---|---|---|

| timer_trigger | object | `{enable, capture_mode(none/interval/once), interval_sec, time_node_count, time_node[] (up to 10 × HH:MM), weekdays[], interval_mode(normal/scheduled), start_time, end_time, anchor, next_capture_at}` |

**timer_trigger fields**:

| Field | Type | Description |
|---|---|---|
| interval_mode | string | `normal` = plain interval; `scheduled` = daily timetable |
| interval_sec | number | lattice step, `1..86399` (strictly under 24 h) when `enable` + `capture_mode=interval`; otherwise `400` |
| start_time | string (GET); string or number (POST) | scheduled mode daily-window start. GET emits `HH:MM` at minute precision; POST accepts `HH:MM` or seconds since local midnight (`0..86399`). If omitted, the current parser sets it to `00:00` |
| end_time | string (GET); string or number (POST) | scheduled mode daily-window end. GET emits `HH:MM` at minute precision; POST accepts `HH:MM` or seconds since local midnight (`0..86399`), and omission preserves the stored value. The window is `[start_time, end_time]` (**end time included**: a node landing exactly on the end fires — e.g. 08:00–08:10 with a 5min interval yields 08:00, 08:05 and 08:10). Must differ from `start_time` (the equal pair is reserved for the normal-mode lattice). **A full-day window is any start T with end T−1min** (the grid is anchored at T and restarts there daily — e.g. 00:00–23:59, 01:00–00:59). `00:00` (with start > `00:00`) ends the window at midnight; an end earlier than the start wraps past midnight (e.g. 20:00→06:00). | anchor | string (GET); string or number (POST) | normal interval-mode time-of-day grid anchor (no date component). GET emits `HH:MM` at minute precision and omits it while unset; POST accepts `HH:MM` or seconds since local midnight (`0..86399`), and omission preserves the stored value (first enable stamps the current time-of-day if still unset). Rolling window `[anchor, anchor+24h)`: nodes are `anchor + n × interval_sec` **flowing continuously past midnight** (anchor 11:00, interval 5 h → 11:00 16:00 21:00 02:00 07:00, all one window); the grid **restarts only at the next anchor instant** (never 12:00), midnight does not reset it; wakes/reboots never re-base the grid. `00:00` cannot be stored explicitly (it is the unset sentinel) |

| pir_trigger | object | `{enable, pin_number, trigger_type(rising_edge/falling_edge/both_edges/high_level/low_level), sensitivity_level(10–255), ignore_time_s(0–15), pulse_count(1–4), window_time_s(0–3), disable_in_preview}` |

## 16. Firmware Upgrade Module (system/ota)

**Shared conventions**

- `firmwareType` values: `fsbl` / `app` / `web` / `ai_default` (AI slot 1) / `ai` (actually active AI slot) / `wifi` / `reserved2`; default `app`
- Package header is 1 KB (`ota_header_t`); AI types carry an extra 1 KB model header (2048 B total)
- Device-model stamp: a package/bundle stamped `device_model ≠ 0 and ≠ 0x3010` is rejected (0 = unstamped legacy, allowed)
- Timeouts: single-upload idle 5 min, bundle-session idle 10 min — auto-terminated, services restarted
- During upload the service automatically stops MQTT, the AI pipeline and the camera (waits ≤30 s for an in-flight capture) and restores them afterwards; **no path auto-reboots**

### 16.1 POST /api/v1/system/ota/precheck — firmware header precheck

**Request**: raw binary body = the first 1024 B of the package (2048 B for AI types); `Content-Type` not enforced.
**Query params**: `firmwareType` (default app), `contentLength` (full package size; if given it must equal the header's `total_package_size`)

**Response data**: `{valid: true, message, firmware_size, firmware_version, firmware_crc32, part_table_changed, device_table_crc, package_table_crc}`

**Failure**: `OTA_HEADER_VALIDATION_FAILED` (1806) with `data:{valid:false, reason}`

### 16.2 POST /api/v1/system/ota/upload — streamed firmware upload

**⚠ Envelope exception**: this endpoint is intercepted by the stream processor before route dispatch (auth handled there; **real HTTP statuses** returned).

| Item | Description |
|---|---|
| Request body | **raw firmware bytes** (not multipart/JSON), 1 KB header + payload |
| Content-Length | **required**, 1024 B – 100 MB |
| Query params | `firmwareType` (default app) |
| Direct-burn mode | `direct=1&addr=0x<addr>`; valid only during a bundle session (`bundle/begin`); `addr` must exactly equal the device-resolved plan address |
| Mutual exclusion | normal upload and bundle sessions are mutually exclusive (an active one rejects the other) |

**Processing**: header verification (magic/CRC/model/type/size) → flash writes in 1 KB chunks with a running CRC32 → final whole-package CRC check. FSBL payloads are staged in PSRAM and flashed only after the CRC passes. WEB uploads reload the web assets immediately; AI uploads set the NVS active-slot flag; WiFi uploads stage the `.rps` at `WIFI_FW_BASE`, pushed at the next reboot.

**Response**: envelope JSON; success `message: "Upgrade successful"`. Failures use real statuses 400 (header verification failed / OTA in progress / params) / 500 (memory/flash/CRC errors).

### 16.3 POST /api/v1/system/ota/upgrade-local — upgrade confirmation (arms WiFi push)

**Request body**: `{firmware_type: "wifi"}` (any other value or an empty body is a no-op)
**Behavior**: for `wifi`, sets the NVS update flag so the next reboot pushes the staged `.rps` to the 917 host.
**Response data**: `null`, `message: "OK"`

### 16.4 POST /api/v1/system/ota/export — export firmware (envelope exception)

**Request body** (JSON; Content-Type must be application/json)

| Field | Type | Required | Description |
|---|---|---|---|
| firmware_type | string | yes | see shared conventions; `ai` resolves to the actually active slot |
| filename | string | yes | export file name (used in Content-Disposition) |

**Response**: raw firmware bytes (`application/octet-stream` + `Content-Disposition`), streamed in 1 KB chunks.

### 16.5 POST /api/v1/system/ota/bundle/precheck — full-reflash bundle precheck

One-click full-reflash bundle (4 KB header + sub-packages). **Request body = the first 4096 bytes of the bundle file** (raw binary).

**Validation**: header magic/size/CRC; device-model stamp; entry table; partition layout physically valid (no overlap, within flash, FSBL must not move); legal types without duplicates; required partitions present; entries fit their partitions; a layout-changing bundle must contain FSBL.

**Response data**

```jsonc
{
  "layout_changed": false,
  "layout_diff": [ { "part": "...", "device_base": 0, "device_size": 0,
                     "bundle_base": 0, "bundle_size": 0 } ],   // only when layout_changed
  "total_bytes": 0,
  "entries": [ {
      "type": "app",            // fsbl|app|web|ai|wifi
      "fw_type": 2,             // raw code: 0x01 fsbl / 0x02 app / 0x03 web / 0x04,0x05 AI / 0x08 wifi
      "skippable": true,        // same version AND unmoved partition (FSBL additionally needs unchanged layout)
      "cur_version": "…", "new_version": "…",
      "size": 0,                // sub-package bytes
      "offset": 4096,           // byte offset within the bundle file
      "addr": 0                 // device-resolved absolute flash burn address
  } ]
}
```

**Side effects**: the validated header + plan is stored as the global bundle session (`prechecked=true`); expires after 10 idle minutes.

### 16.6 POST /api/v1/system/ota/bundle/begin — start the bundle forced-reflash session

**Request body**: `{skip?: ["wifi", "fsbl", ...]}` — skip list; names must be in the plan and `skippable=true`; **skipping everything is rejected**.

**Response data**: `{burn_count}`, `message: "Bundle session started"`

**⚠ Side effect**: every begin **erases the OTA info partition**; the next boot rebuilds SystemState from the new layout (slot A / APP1 / AI_1 active). Skipping `wifi` clears the pending-WiFi-push flag.

### 16.7 POST /api/v1/system/ota/bundle/finish — finish/abort the bundle session

**Request body**: `{result: "ok" | "abort"}` (anything other than "ok" is treated as abort)
**Behavior**: on `"ok"` with a WiFi update still in the plan, calls `wifi_mark_update_pending()`; the session is cleared either way, **no auto-reboot** (the frontend then calls `/system/restart`). Already-burned firmware is not rolled back; abort is idempotent.
**Response data**: `{wifi_pending}`, `message: "Bundle finished"/"Bundle aborted"`

## 17. ISP Image Quality Module (isp)

**Shared error codes** (business codes 2001–2008, see 1.5.2): 2001 not initialized / 2002 invalid param (JSON) / 2003 out of range / 2004 dependency / 2005 HAL / 2006 sensor / 2007 algorithm / 2008 busy.

**General semantics**: GET returns current values; PUT **applies live to the ISP hardware** and updates the IQ-parameter cache but **does not write NVS by itself** — persist via `POST /isp/config/save`. GETs additionally carry `_meta` (field metadata: type/unit/range/default).

### 17.1 GET /api/v1/isp/params — all parameters

**Response data**: `{sensor_info:{name,bayer_pattern,color_depth,width,height}, aec, awb, demosaicing, stat_removal, black_level, bad_pixel, isp_gain, color_conv, contrast, gamma, stat_area, sensor_delay}` (group fields as in the corresponding endpoints below)

### 17.2 GET /api/v1/isp/sensor — sensor information

**Response data**: `{name, bayer_pattern(RGGB/GRBG/GBRG/BGGR/MONO), color_depth, width, height, gain_range:{min,max}, exposure_range:{min,max}}` (gain in mB, exposure in µs)

### 17.3 GET /api/v1/isp/statistics — ISP statistics

**Response data**: `{down:{average_r,average_g,average_b,average_l,histogram[12]}, up:{average_r,average_g,average_b,average_l}, estimated_lux, frame_id}` (down = after ISP processing, up = before)

### 17.4 GET / PUT /api/v1/isp/aec — auto exposure

| Field | Type | Range | PUT |
|---|---|---|---|
| enable | bool | — | ✅ |
| exposure_compensation | number | −4…+4 (0.5 EV steps, i.e. ±2.0 EV) | ✅ |
| anti_flicker_freq | number | 0 / 50 / 60 | ❌ (read-only here; settable only via import) |

GET also carries `current_state:{sensor_gain, sensor_exposure, estimated_lux}`.

### 17.5 GET / PUT /api/v1/isp/aec/manual — manual exposure

| Field | Type | Range | Description |
|---|---|---|---|
| gain | number | sensor.gain_min…max | unit mB |
| exposure | number | sensor.exposure_min…max | unit µs |

> Manual exposure takes effect only while AEC is **disabled** (see GET `_meta.dependencies`).

### 17.6 GET / PUT /api/v1/isp/awb — auto white balance

| Field | Type | Description |
|---|---|---|
| enable | bool | AWB switch |
| mode | string | `auto` (profile by scene) / `manual` (by color_temp) |
| color_temp | number | manual-mode color temp (PUT consumes it together with `mode`) |
| profiles | array | exactly 5: `{index(0–4), label(≤31 chars), reference_color_temp, isp_gain:{r,g,b}, ccm[3][3](±4.0×), reference_rgb:{r,g,b}}` |

GET also carries `current_color_temp, current_gains:{r,g,b}, current_ccm:{enable, matrix}`. Profile numbers have no range validation and are written straight into the IQ cache.

### 17.7 GET / PUT /api/v1/isp/demosaicing — demosaicing

`{enable, peak, line_v, line_h, edge}` (strengths all 0–7, default 4); `bayer_type` read-only (sensor-determined).

### 17.8 GET / PUT /api/v1/isp/stat_removal — statistics line removal

`{enable, head_lines(0–7), valid_lines(0–4094)}`

### 17.9 GET / PUT /api/v1/isp/black_level — black level

`{enable, r, g, b}` (each 0–255, default 12)

### 17.10 GET / PUT /api/v1/isp/bad_pixel — bad-pixel correction

`{enable, strength(0–7), detected_count(read-only, runtime-detected), algo_enable, algo_threshold(≥0)}`

### 17.11 GET / PUT /api/v1/isp/gain — ISP digital gain

`{enable, r, g, b}`, unit **100000000 = 1.0×**, max 16.0× (1,600,000,000).
> ISP gain is auto-controlled while AWB is enabled.

### 17.12 GET / PUT /api/v1/isp/color_conv — color conversion matrix

`{enable, matrix[3][3]}`, coefficients ±399,000,000 (1e8 = 1.0×); must be exactly 3×3.

### 17.13 GET / PUT /api/v1/isp/contrast — contrast LUT

`{enable, lut[9]}`, each 0–394 (luma anchors [0,32,…,256], 100 = 1.0×); must be exactly 9 items.

### 17.14 GET / PUT /api/v1/isp/gamma — gamma correction

`{enable}` (the only field)

### 17.15 GET / PUT /api/v1/isp/stat_area — statistics window

`{x, y, width, height}`, width/height ≥ 4 and ≤ 4094; must satisfy `x+width ≤ sensor_width`, `y+height ≤ sensor_height`. PUT merges with current values.

### 17.16 GET / PUT /api/v1/isp/lux_ref — lux reference (AEC estimation input)

`{high_lux:{lux_ref,expo1,lum1,expo2,lum2}, low_lux:{…same…}, calib_factor(float)}`; lum1/lum2 are 0–255. IQ cache only.

### 17.17 GET / PUT /api/v1/isp/sensor_delay — sensor delay

`{delay}` (int ≥ 0, stored as uint8). IQ cache only.

### 17.18 POST /api/v1/isp/config/save — persist IQ parameters to NVS

**Request body**: empty. Saves all current live IQ parameters. **Response**: `message: "ISP configuration saved successfully"`.

### 17.19 POST /api/v1/isp/config/load — load from NVS

**Request body**: empty. Without a saved config returns 2001 (`No saved ISP configuration found`).
> ⚠ In the current code the actual apply call is commented out; the handler only verifies a config exists and then reports success — firmware behavior prevails.

### 17.20 GET /api/v1/isp/config/export — export IQ configuration

**Response data**: `{export_version:"1.0", export_timestamp, config:{stat_removal, demosaicing{+type}, contrast, stat_area, bad_pixel{algo_*, static_*}, black_level, aec, awb{profiles[{label,color_temp,gain_r,gain_g,gain_b,ccm[9 flat]}]}, isp_gain, color_conv{matrix[9 flat]}, gamma, sensor{gain,exposure,delay}, lux_ref{hl_*,ll_*,calib_factor}}}`

> Export field names differ slightly from the per-parameter API (`color_temp`/`gain_r|g|b`/flat 9-element arrays).

### 17.21 POST /api/v1/isp/config/import — import IQ configuration

**Request body**: `{config: {…same structure as export…}}` (`config` required; inner sections optional; `ccm`/`matrix` accept flat arrays of ≥9 items)

**Behavior**: applies live + persists to NVS + refreshes the device cache. **No range validation** (unlike the individual PUTs).
**Response**: `message: "ISP configuration imported and applied successfully"`

## Appendix A. curl Quick Start

```bash
# Every request carries Basic auth (username admin)
curl -u admin:<password> http://<device-ip>/api/v1/device/info

# Branch on the success field, not the HTTP status
curl -s -u admin:12345678 http://<device-ip>/api/v1/ai/status | jq .success

# File upload (raw byte stream, not multipart)
curl -u admin:<password> -X POST --data-binary @frame.jpg \
  "http://<device-ip>/api/v1/files/upload?fs=sd&path=/photos/frame.jpg"

# OTA upload (streamed, real status codes)
curl -u admin:<password> -X POST --data-binary @app_v4.3.1.x.bin \
  "http://<device-ip>/api/v1/system/ota/upload?firmwareType=app"
```

## Appendix B. WebSocket Preview Stream

| Item | Value |
|---|---|
| URL | `ws://<device-ip>:8081/stream` (separate listener, default port 8081) |
| Payload | H.264 video frames; GOP ≈ 1 s |
| Keyframe sync | the server performs per-subscriber keyframe join-sync: on each keyframe it sends a single `[SPS][PPS][IDR]` composite frame, so late-joining clients never see a black screen |
| Lifecycle | `POST /api/v1/preview/start` starts the pipeline; after the last client disconnects, `POST /api/v1/preview/stop` actually stops the stream |

> Players should use a decoder that accepts Annex-B start codes (e.g. jmuxer); the first frame already includes the parameter sets — no separate SPS/PPS request is needed.
