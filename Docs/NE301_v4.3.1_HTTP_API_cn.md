## 1. 通用约定

### 1.1 服务与基础地址

| 项目 | 值 |
|---|---|
| HTTP 服务 | Mongoose,监听 **TCP 80** 端口 |
| HTTPS | 未启用(`IS_HTTPS=0`) |
| API 基础路径 | **`/api/v1`** |
| 单请求体上限 | 5 MB(经路由器的普通请求) |
| 连接模式 | `Connection: close`,一连接一请求 |
| 静态资源 | Web UI 由根路径 `/` 直接提供(支持 ETag/304/gzip) |

设备地址:
- STA/以太网模式:设备获得的 IP(见路由器/AP,或经配置工具查询)
- AP 模式:设备热点网关地址(默认 `10.10.10.1` 网段,以设备实际配置为准)

### 1.2 认证

- 采用 **HTTP Basic 认证**,每个请求独立校验,无会话/Cookie。
- 用户名固定 **`admin`**(`auth_mgr.h: AUTH_ADMIN_USERNAME`),密码为设备访问密码。
- 密码可经 `POST /api/v1/login` 校验、经 `POST /api/v1/change-password` 修改。

**免认证端点**(路由表中 `require_auth=false`):

| 端点 | 说明 |
|---|---|
| `POST /api/v1/login` | 密码校验 |
| `GET /api/v1/preview/status` | 预览状态 |
| `POST /api/v1/preview/start` | 启动预览 |
| `POST /api/v1/preview/stop` | 停止预览 |

> 注:`POST /api/v1/system/ota/upload` 在路由分发之前被流式拦截器接管,自行校验,详见 16.2 节。

**认证失败响应**(普通接口):HTTP 状态码仍为 **200**,信封内 `error_code: "UNAUTHORIZED"`。流式上传接口(`files/upload`、`ota/upload`)例外,返回真实 `401`。

### 1.3 统一响应信封

所有经路由器的接口,无论成功失败,**HTTP 状态码恒为 200**,正文为 JSON 信封:

```jsonc
// 成功
{
  "success": true,
  "message": "Device information retrieved successfully",   // 可选
  "data": { ... }                                            // 可选
}

// 失败
{
  "success": false,
  "error_code": "INVALID_PASSWORD",   // 仅失败时出现,字符串名
  "message": "Invalid password"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| success | bool | 业务成败 |
| error_code | string | 仅失败时出现,大写下划线字符串(见 1.5) |
| message | string | 人读描述,成功/失败均可能出现 |
| data | object/array/null | 业务数据,可能缺省 |

> **客户端务必以 `success` 字段判错,不能依赖 HTTP 状态码。**

### 1.4 信封例外(返回真实 HTTP 状态码/非 JSON 的接口)

| 接口 | 响应形式 |
|---|---|
| `GET /api/v1/files/download` | 原始文件字节流 + `Content-Disposition`(404/400 为信封 JSON) |
| `GET /api/v1/files/preview` | 图片原始字节;文本文件为 JSON(content 为字符串) |
| `POST /api/v1/files/upload` | 流式直写,认证失败 **401**、参数错 400、内部错 500/503(真实状态码) |
| `POST /api/v1/system/ota/upload` | 流式直写,真实状态码 400/401/500 |
| `POST /api/v1/system/ota/export` | 原始固件字节流 + `Content-Disposition` |
| `GET /` 静态资源 | 200/304/404 |
| `OPTIONS` 预检 | 200 + CORS 头 |

### 1.6 CORS 与预检

所有响应携带 CORS 头(`Access-Control-Allow-Origin: *` 等);`OPTIONS` 预检请求直接返回 200 + CORS 头,不进入业务路由。

### 1.7 实时预览流(WebSocket,非 HTTP API)

预览流走独立 WebSocket 服务:**`ws://<设备IP>:8081/stream`**(默认端口 8081、路径 `/stream`)。详见[附录 B](#附录-b-websocket-预览流)。

## 3. 认证模块(auth)

### 3.1 POST /api/v1/login — 校验设备密码

**免认证。** 用于前端登录页校验密码(用户名固定 `admin`,不随请求传递)。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| password | string | 是 | 设备访问密码 |

**响应 data**:`null`(成功时仅有 `success:true` + message)

**错误**:`INVALID_REQUEST`(缺参);`INVALID_PASSWORD`(1001,密码错误)

### 3.2 POST /api/v1/change-password — 修改设备密码

**请求体**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| password | string | 是 | 新密码,**长度 8–32 字符** |

**响应 data**:`null`

**说明**:修改立即生效,后续请求需用新密码做 Basic 认证。

**错误**:`INVALID_REQUEST`(缺参/长度非法);`INVALID_PASSWORD`(修改失败)

**查询参数**

| 参数 | 说明 |
|---|---|
| state | 过滤状态(pending/sent/failed/local) |
| offset / limit | 分页,limit ≤ 200 |
| from / to | 时间戳范围 |
| sort | 排序 |

**响应 data**:`{state, offset, limit, total, records:[{id, state, timestamp, size, retry_count, trigger, last_error, has_inference}]}`

`total` 是分页**下界**，不一定是过滤结果的完整计数。实现会多取一条作为 lookahead：末页 `total = offset + records.length`，此时为精确值；仍有更多记录时 `total = offset + records.length + 1`。客户端只应据此判断是否可能还有下一页。

`has_inference` 表示记录元数据含非空 `inference_image` 路径；接口不会 stat 或验证对应文件，因此即使为 `true`，也不保证推理图片仍存在或可打开。

| end_time | string（GET）；string 或 number（POST） | 定时间隔每日窗口结束。GET 以 `HH:MM` 返回，精度为分钟；POST 接受 `HH:MM` 或当天零点起秒数（`0..86399`），省略则保留已存值。窗口为 `[start_time, end_time]`（**含结束时刻**：结束点恰落在网格上也会抓拍，如 8:00–8:10、间隔 5 分钟 → 8:00、8:05、8:10）。不得与 start_time 相同（相等组合保留给普通模式的全天网格）；**全天窗口=任意起点 T 配 T−1 分钟**（锚点即 T，网格从 T 起每天重启，如 00:00–23:59、01:00–00:59）；`00:00`（起始非 00:00）表示到午夜为止；结束早于起始则跨零点（如 20:00→06:00）。窗口（含端点）必须能容纳至少两个节点（即长于 interval_sec），否则 `400`。当天最后一个节点之后，下次抓拍为下一个窗口起始 |
| anchor | string（GET）；string 或 number（POST） | 普通间隔模式的日内网格锚点（不含日期）。GET 以 `HH:MM` 返回，精度为分钟，未设置时省略；POST 接受 `HH:MM` 或当天零点起秒数（`0..86399`），省略则保留已存值（仍未设置时，首次启用会写入当前日内时刻）。滚动窗口 `[锚点, 锚点+24h)`，节点为 `anchor + n × interval_sec`，**连续排过午夜不打断**（锚点 11:00、间隔 5 小时 → 11:00 16:00 21:00 02:00 07:00，同属一窗）；**到下一个锚点整点才重新开窗**（永不出现 12:00），午夜不重置；唤醒/重启不会重置网格。`00:00` 为未设置哨兵，不能显式存储 |
| next_capture_at | number | 仅 GET；没有下一节点时省略。下次抓拍节点为 Unix 秒，与调度器使用同一套网格计算；POST 中携带该字段会被忽略 |
| pir_trigger | object | `{enable, pin_number, trigger_type(rising_edge/falling_edge/both_edges/high_level/low_level), sensitivity_level(10–255), ignore_time_s(0–15), pulse_count(1–4), window_time_s(0–3), disable_in_preview}` |
| remote_trigger | object | `{enable}` |
| io_trigger | object | `{id, pin_number, enable, input_enable, output_enable, input_trigger_type, output_trigger_type}` |
| image_mode / video_stream_mode | object | 同 11.1 |

## 16. 固件升级模块(system/ota)

**共享约定**

- `firmwareType` 取值:`fsbl` / `app` / `web` / `ai_default`(AI 槽 1)/ `ai`(实际活跃 AI 槽)/ `wifi` / `reserved2`,默认 `app`
- 包头 1 KB(`ota_header_t`);AI 类型另带 1 KB 模型包头(共 2048 B)
- 型号戳:包/Bundle 标注 `device_model ≠ 0 且 ≠ 0x3010` 一律拒绝(0=旧包放行)
- 超时:单包上传空闲 5 分钟、Bundle 会话空闲 10 分钟自动终止并恢复服务
- 上传期间自动停止 MQTT、AI 流水线、相机(等待在途抓拍 ≤30 秒),结束后恢复;**任何路径均不自动重启**

### 16.1 POST /api/v1/system/ota/precheck — 固件包头预检

**请求**:原始二进制体 = 包前 1024 B(AI 类型 2048 B),`Content-Type` 不强制。
**查询参数**:`firmwareType`(默认 app)、`contentLength`(整包大小,给出则须与头一致)

**响应 data**:`{valid: true, message, firmware_size, firmware_version, firmware_crc32, part_table_changed, device_table_crc, package_table_crc}`

**失败**:`OTA_HEADER_VALIDATION_FAILED`(1806),且 `data:{valid:false, reason}`

### 16.2 POST /api/v1/system/ota/upload — 流式固件上传

**⚠ 信封例外**:该端点在路由分发前被流式拦截器接管(自行校验认证,返回**真实 HTTP 状态码**)。

| 要素 | 说明 |
|---|---|
| 请求体 | **原始固件字节流**(非 multipart/JSON),1 KB 头 + 载荷 |
| Content-Length | **必需**,1024 B – 100 MB |
| 查询参数 | `firmwareType`(默认 app) |
| 直接烧写模式 | `direct=1&addr=0x<地址>`,仅在 Bundle 会话(`bundle/begin`)有效,须与设备解析的计划地址一致 |
| 互斥 | 普通上传与 Bundle 会话互斥(进行中一方拒绝另一方) |

**处理**:头校验(magic/CRC/型号/类型/大小)→ 逐 1 KB 写 flash 并滚动 CRC32 → 末尾校验整包 CRC。FSBL 载荷先暂存 PSRAM,CRC 通过后才擦写。WEB 类型上传后立即重载 Web 资源;AI 类型写 NVS 活跃槽标志;WiFi 类型暂存 `.rps` 于 `WIFI_FW_BASE`,重启时推送。

**响应**:信封 JSON;成功 `message: "Upgrade successful"`。失败真实状态码 400(头校验失败/OTA 进行中/参数)/500(内存/flash/CRC 错误)。

### 16.3 POST /api/v1/system/ota/upgrade-local — 升级确认(WiFi 推送待命)

**请求体**:`{firmware_type: "wifi"}`(其他值/空体为 no-op)
**行为**:`wifi` 时置 NVS 更新标志,下次重启把暂存的 `.rps` 推给 917 主机。
**响应 data**:`null`,`message: "OK"`

### 16.4 POST /api/v1/system/ota/export — 导出固件(信封例外)

**请求体**(JSON,Content-Type 必须为 application/json)

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| firmware_type | string | 是 | 见共享约定;`ai` 解析为实际活跃槽 |
| filename | string | 是 | 导出文件名(用于 Content-Disposition) |

**响应**:原始固件字节流(`application/octet-stream` + `Content-Disposition`),1 KB 分块。

### 16.5 POST /api/v1/system/ota/bundle/precheck — 整机 Bundle 预检

一键重刷包(4 KB 头 + 各子包)。**请求体 = Bundle 文件前 4096 字节**(原始二进制)。

**校验**:头 magic/大小/CRC、型号戳、条目表、分区表物理合法(无重叠、不越界、FSBL 不可移动)、类型合法且无重复、必含分区、条目不超分区、改布局包必须含 FSBL。

**响应 data**

```jsonc
{
  "layout_changed": false,
  "layout_diff": [ { "part": "...", "device_base": 0, "device_size": 0,
                     "bundle_base": 0, "bundle_size": 0 } ],   // 仅 layout_changed 时
  "total_bytes": 0,
  "entries": [ {
      "type": "app",            // fsbl|app|web|ai|wifi
      "fw_type": 2,             // 原始码: 0x01 fsbl / 0x02 app / 0x03 web / 0x04,0x05 AI / 0x08 wifi
      "skippable": true,        // 版本相同且分区未动(FSBL 另需布局未变)
      "cur_version": "…", "new_version": "…",
      "size": 0,                // 子包字节数
      "offset": 4096,           // 在 Bundle 文件内的字节偏移
      "addr": 0                 // 设备侧解析出的绝对烧写地址
  } ]
}
```

**副作用**:预检结果驻留为全局 Bundle 会话(`prechecked=true`),10 分钟空闲过期。

### 16.6 POST /api/v1/system/ota/bundle/begin — 启动 Bundle 强刷会话

**请求体**:`{skip?: ["wifi", "fsbl", ...]}`——跳过清单,名字必须在计划内且 `skippable=true`;**全部跳过会被拒绝**。

**响应 data**:`{burn_count}`,`message: "Bundle session started"`

**⚠ 副作用**:每次 begin 都会**擦除 OTA info 分区**,下次开机按新布局重建 SystemState(槽 A/APP1/AI_1 活跃)。跳过 `wifi` 会清除 WiFi 待推送标志。

### 16.7 POST /api/v1/system/ota/bundle/finish — 结束/中止 Bundle 会话

**请求体**:`{result: "ok" | "abort"}`(非 "ok" 一律按 abort)
**行为**:`ok` 且计划含 WiFi 更新时置 `wifi_mark_update_pending()`;会话清空,**不自动重启**(由前端随后调 `/system/restart`)。已烧写的固件不回滚,abort 幂等。
**响应 data**:`{wifi_pending}`,`message: "Bundle finished"/"Bundle aborted"`

`{delay}`(int ≥ 0,存 uint8)。仅写 IQ 缓存。

### 17.18 POST /api/v1/isp/config/save — 持久化 IQ 参数到 NVS

**请求体**:空。保存当前全部实时 IQ 参数。**响应**:`message: "ISP configuration saved successfully"`。

### 17.19 POST /api/v1/isp/config/load — 从 NVS 加载

**请求体**:空。无保存配置时报 2001(`No saved ISP configuration found`)。
> ⚠ 当前代码中实际应用调用被注释,仅校验配置存在即返回成功文案,以固件行为为准。

### 17.20 GET /api/v1/isp/config/export — 导出 IQ 配置

**响应 data**:`{export_version:"1.0", export_timestamp, config:{stat_removal, demosaicing{+type}, contrast, stat_area, bad_pixel{algo_* ,static_*}, black_level, aec, awb{profiles[{label,color_temp,gain_r,gain_g,gain_b,ccm[9]平铺}]}, isp_gain, color_conv{matrix[9]平铺}, gamma, sensor{gain,exposure,delay}, lux_ref{hl_*,ll_*,calib_factor}}}`

> 导出字段名与单参数 API 略有差异(`color_temp`/`gain_r|g|b`/平铺 9 元素数组)。

### 17.21 POST /api/v1/isp/config/import — 导入 IQ 配置

**请求体**:`{config: {…同 export 结构…}}`(`config` 必需,内部各节可选;`ccm`/`matrix` 接受 ≥9 元素平铺数组)

**行为**:实时应用 + 持久化 NVS + 刷新设备缓存。**不做范围校验**(与单参数 PUT 不同)。
**响应**:`message: "ISP configuration imported and applied successfully"`

## 附录 B. WebSocket 预览流

| 项 | 值 |
|---|---|
| 地址 | `ws://<设备IP>:8081/stream`(独立监听,默认端口 8081) |
| 数据 | H.264 视频帧;GOP ≈ 1 秒 |
| 关键帧同步 | 服务端为每个新订阅者做关键帧 join-sync:关键帧到达时拼接 `[SPS][PPS][IDR]` 单帧发送,晚连客户端不会黑屏 |
| 生命周期 | `POST /api/v1/preview/start` 启动流水线;最后一个客户端断开后 `POST /api/v1/preview/stop` 真正停流 |

> 播放端建议使用支持 Annex-B 起始码的解码器(如 jmuxer);首帧即含参数集,无需额外请求 SPS/PPS。
